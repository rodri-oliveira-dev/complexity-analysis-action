# Complexity Analysis Action v1.0.0

## Overview

Complexity Analysis helps .NET teams analyze C# projects in GitHub Actions,
apply explicit quality gates, and review proven complexity regressions in pull
requests. It performs structural analysis and algorithmic-complexity estimation;
it is not a runtime benchmark and does not predict exact execution time.

## Key capabilities

- Analyze `.csproj`, `.sln`, and `.slnx` entry points, including paths with spaces.
- Produce validated JSON and SARIF 2.1.0 reports.
- Enforce opt-in Big-O, cyclomatic, cognitive, nesting, NLOC, and duplication gates.
- Generate deterministic snapshots and compare a pull-request head with its base.
- Distinguish proven regressions from improvements, equivalent, ambiguous, and
  incomparable results.
- Write a GitHub Job Summary and optionally publish a bounded PR comment.

## Supported environment

The v1 contract supports GitHub-hosted Ubuntu runners. Windows and macOS are not
supported because equivalent end-to-end suites have not passed. The Action
installs .NET SDK 10.0.403 and the exact published `ComplexityAnalysis.Tool`
1.0.1 package, which targets `net10.0` and requires .NET 10.

## Basic usage

After publication, replace `v1.0.0` with a full release commit SHA when immutable
consumption is required:

```yaml
permissions:
  contents: read

steps:
  - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1
    with:
      persist-credentials: false
  - uses: rodri-oliveira-dev/complexity-analysis-action@v1.0.0
    with:
      path: MySolution.slnx
```

`v1.0.0` and `v1` do not exist until the approved release is published. The
release-specific tag is immutable; `v1` is the maintained compatible reference.

## Inputs and outputs

The public inputs, defaults, outputs, and status values are documented in the
[README](../../README.md#inputs). Quality gates are opt-in and reports are
created before a configured gate or regression policy is applied.

## Security considerations

Use `contents: read` for analysis and do not expose secrets or write-capable
credentials to untrusted project evaluation. MSBuild project loading can execute
repository-controlled logic. Never analyze pull-request code under
`pull_request_target`; the Action rejects that event. Fork PR feedback uses the
documented report-only `workflow_run` publisher, which never executes PR code.

## Known limitations

- Ubuntu only; no Windows or macOS support.
- No process or network sandbox for MSBuild evaluation.
- Comparison requires the configured entry-point path in both revisions.
- Comparison SARIF is generated locally but is not uploaded automatically.
- Optional Code Scanning and PR publication depend on repository availability
  and explicitly granted GitHub token permissions.
